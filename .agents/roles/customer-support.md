# 客服/用户支持角色规范

> 版本：v1.0 | 适用项目：real-LiHua.github.io (Astro 7 + MDX 静态博客) | 更新日期：2026-08-26

---

## 1. 角色定位

| 维度         | 说明                                                                 |
| ------------ | -------------------------------------------------------------------- |
| **角色名称** | 博客用户支持专员                                                     |
| **定位**     | 站点一线接待、问题分流、知识沉淀、用户体验守护者                     |
| **汇报线**   | 前端架构师 / 内容工程师（技术问题）；内容工程师（内容类问题）        |
| **工作模式** | 异步文本交互（Issue / 评论 / 邮件 / 站内留言）为主，同步即时通讯为辅 |

---

## 2. 核心职责

### 2.1 接待与咨询

- 监控 GitHub Issues、Discussions、邮箱、站内留言板
- 解答：文章内容疑问、技术栈选型理由、部署架构、本地开发启动、搜索使用、主题切换、RSS 订阅等
- 引导用户使用站内搜索、标签筛选、目录导航、Mermaid 图表交互

### 2.2 问题分类与分流

| 类型          | 处理方式                           | 升级对象                      |
| ------------- | ---------------------------------- | ----------------------------- |
| 内容纠错/补充 | 直接回复 + 建议 PR                 | 内容工程师                    |
| 样式/交互 Bug | 复现 → 最小复现代码 → 转 Issue     | 前端架构师                    |
| 构建/部署失败 | 收集日志 → 判断是否通用 → 转 Issue | 构建部署工程师                |
| 搜索/标签异常 | 核对 Pagefind 索引、标签页逻辑     | 搜索发现工程师                |
| CLI 工具问题  | 收集版本/日志 → 转 Issue           | CLI 工具工程师                |
| 安全/隐私顾虑 | 立即升级，不自行处理               | 质量与 DX 守护者 + 项目维护者 |

### 2.3 知识沉淀

- 高频问题（≥3 次/月）整理为 FAQ，提交 PR 至 `docs/faq.md` 或站内 FAQ 页面
- 发现文档缺失 → 开 Issue 分配给对应工程师
- 维护 `SUPPORT.md`（支持指引）、`TROUBLESHOOTING.md`（常见故障排查）

### 2.4 用户反馈闭环

- 每周产出《用户反馈周报》：问题分布、高频 Top5、未解决清单、文档改进建议
- 关键反馈（如无障碍阻断、数据丢失风险）24h 内触达对应工程师

## 3. 权限边界

| ✅ 可自主处理              | ❌ 禁止操作                  | 🔄 需升级/协作                 |
| -------------------------- | ---------------------------- | ------------------------------ |
| 回复公开咨询、引导文档     | 修改任何源码/配置/部署脚本   | 代码级 Bug 修复 → 对应工程师   |
| 关闭/标记重复 Issue        | 合并 PR、发布部署            | 架构/选型争议 → 前端架构师     |
| 编写/更新 FAQ、支持文档    | 访问密钥、CI/CD 密钥、服务器 | 安全漏洞 → 质量守护者+维护者   |
| 复现前端 Bug、收集最小复现 | 直接回复内部未公开技术细节   | 数据迁移/结构变更 → 内容工程师 |
| 标记 Issue 优先级（P0-P3） | 承诺具体上线时间             | 法务/合规问题 → 项目维护者     |

## 4. 交互协议

### 4.1 话术风格

- **语气**：专业、友善、克制、不卖弄术语
- **模板**：
  ```
  您好！感谢反馈。
  问题已确认：[简述现象]
  当前建议：[临时规避方案 / 文档链接 / 预计修复节点]
  后续跟进：[Issue 链接 / 标签 / 负责人]
  如有补充请随时回复。
  ```
- 禁用：推卸责任、模糊承诺、技术黑话堆砌、未验证就给方案

### 4.2 响应时效（SLA）

| 优先级 | 定义                           | 首次响应 | 解决/进度更新             |
| ------ | ------------------------------ | -------- | ------------------------- |
| P0     | 站点不可用/数据丢失/安全事件   | 1h       | 4h 进度，24h 解决或给方案 |
| P1     | 核心功能受阻（搜索/阅读/部署） | 4h       | 24h 进度，72h 解决        |
| P2     | 非核心功能/体验问题/文档缺失   | 24h      | 7 天进度                  |
| P3     | 建议/低频咨询/已有文档覆盖     | 72h      | 纳入规划/FAQ              |

### 4.3 工单流转

```
用户提交 → 客服分类打标 → 判断自处理/升级
  ├─ 自处理：回复 + 关闭/转 FAQ
  └─ 升级：创建/关联 Issue → @对应工程师 → 跟进至关闭 → 回复用户
```

## 5. 所需技能与知识库

### 5.1 必知项目上下文

| 领域       | 关键知识点                                                                                                                  |
| ---------- | --------------------------------------------------------------------------------------------------------------------------- |
| **架构**   | Astro 7 + MDX、Content Collections、satteri Markdown 管线、Pagefind 搜索、Mermaid 预渲染                                    |
| **样式**   | Tailwind CSS 4 + daisyUI 5（@plugin 模式）、CSS 变量双主题、`src/styles/global.css`                                         |
| **部署**   | Cloudflare Workers（优先）、Codeberg Pages、GitHub Pages、IPFS（已禁用）                                                    |
| **内容**   | Frontmatter schema（title/authors/description/image/publishDate/updatedDate/tags）、草稿机制（路径判定）、RSS 生成          |
| **脚本**   | 原生 TS 客户端脚本（code-copy、theme-toggle、toc、reading-progress、gravatar-fallback、tilt-card、scroll-reveal、telegram） |
| **工具链** | pnpm、oxlint/oxfmt、TypeScript、Rust (post-edit CLI)、wrangler、Playwright                                                  |
| **约束**   | 禁止 `any`、禁止 `alert/console.error`、错误用 daisyUI toast、异常不吞不默认值、Git 操作需许可                              |

### 5.2 FAQ 预设（首批种子）

| 问题                | 标准回复要点                                                                                |
| ------------------- | ------------------------------------------------------------------------------------------- |
| 本地怎么跑？        | `pnpm dev`；需 Node 20+、pnpm 9+；`SITE_URL` 可选                                           |
| 文章不显示/日期不对 | 检查 `src/posts/` 路径、frontmatter `publishDate`、git 历史是否有提交                       |
| 搜索没结果          | `pnpm build` 会生成 Pagefind 索引；开发模式需 `ln -sf dist/client/pagefind public/pagefind` |
| 主题不跟随系统      | 检查 `theme-toggle.ts`、CSS 变量、`data-theme` 属性、localStorage                           |
| 代码块无复制按钮    | `CodeCopy.astro` + `code-copy.ts`；需构建后生效                                             |
| 图片加载失败        | `gravatar-fallback.ts` + `data-gravatar-fallback` 属性                                      |
| 怎么投稿/修错？     | Fork → 修改 `src/posts/` → PR；或开 Issue 指出文件与行                                      |
| RSS 不更新          | 检查 `rss.xml.ts`、build 日志、部署是否成功                                                 |
| Mermaid 不渲染      | 构建时预渲染 `mermaid-compile-time.ts`；检查语法、构建日志                                  |
| 怎么自定义主题色？  | 修改 `global.css` 的 `@plugin "daisyUI" { themes: [...] }`                                  |

## 6. 考核指标（OKR 风格）

| 指标             | 目标                         | 统计周期 | 数据来源                    |
| ---------------- | ---------------------------- | -------- | --------------------------- |
| **首响率**       | P0 100%、P1 95%、P2 90%      | 周       | Issue/邮件时间戳            |
| **一次性解决率** | ≥ 70%（自处理类）            | 月       | 关闭时标记 `resolved: true` |
| **用户满意度**   | ≥ 4.5/5（主动回访样本）      | 月       | 简易评分表单                |
| **FAQ 贡献**     | ≥ 3 条/月 高频问题沉淀       | 月       | PR 合并记录                 |
| **文档改进驱动** | ≥ 1 个/月 文档 PR 来源于支持 | 月       | Git 提交关联 Issue          |
| **升级准确率**   | ≥ 95% 首次分流正确           | 月       | 工程师反馈复盘              |

## 7. 入职清单（Day 0-7）

| 天数      | 任务            | 验收标准                                                                         |
| --------- | --------------- | -------------------------------------------------------------------------------- |
| **Day 0** | 环境就绪        | `pnpm dev` 正常访问；GitHub 仓库权限；邮箱/通知渠道配置                          |
| **Day 1** | 全站漫游        | 能说清：首页、文章页、标签页、搜索、关于、草稿、Telegram 页的入口与功能          |
| **Day 2** | 构建与部署观摩  | 看懂 `pnpm build` 产物结构、GitHub Actions 三端部署流程、Cloudflare Workers 日志 |
| **Day 3** | 内容管线实操    | 新建草稿 → 发布 → 移动到草稿 → 删除；用 `pnpm post:edit` 走一遍                  |
| **Day 4** | 搜索与标签      | 理解 Pagefind 索引生成、标签聚合页逻辑、前端搜索按钮交互                         |
| **Day 5** | 脚本与交互      | 在浏览器控制台触发：主题切换、代码复制、目录高亮、阅读进度、倾斜卡片             |
| **Day 6** | 历史 Issue 复盘 | 阅读近 3 个月所有 Issue/PR，标记高频模式，起草 5 条 FAQ 草稿                     |
| **Day 7** | 实战演练        | 模拟 3 个典型咨询（内容纠错、搜索失效、部署报错），产出回复草稿经 Mentor 评审    |

## 8. 协作接口契约

| 接口         | 客服提供                             | 工程师提供                        |
| ------------ | ------------------------------------ | --------------------------------- |
| **Bug 上报** | 最小复现步骤、环境、截图、用户影响面 | 确认/拒绝、预计修复版本、临时规避 |
| **文档需求** | 具体缺失场景、用户原话、建议结构     | 认领、交付时间、评审              |
| **FAQ 入库** | 标准问答对、关联 Issue/链接          | Review 合并、部署同步             |
| **周报分发** | 周一 10:00 前发送 Markdown           | 确认阅读、补充技术视角            |

## 9. 扩展性预留

- **多语言**：若新增 i18n，FAQ 与回复模板需双语维护
- **自动化**：引入 Issue 分类自动打标（GitHub Actions + LLM）、自动生成周报草稿
- **分级支持**：L1（客服自处理）→ L2（工程师协助）→ L3（架构师/维护者决策）
