# 架构设计技能

## 适用场景

- 新系统/子系统架构设计
- 现有架构重构与演进
- 模块边界划分与解耦
- 技术栈选型与评估
- 性能瓶颈架构级分析

## 核心方法论

### 1. 架构决策记录 (ADR)

```bash
# 创建新 ADR
node .agents/scripts/create-adr.ts "引入新状态管理库"

# 模板包含：Context、Decision、Consequences、Alternatives
```

### 2. 模块边界分析

- **高内聚**：单一职责、相关功能聚合
- **低耦合**：定义清晰接口、最小化依赖
- **显式契约**：TypeScript 接口、Zod schema、OpenAPI spec

### 3. 技术选型矩阵

| 维度       | 权重 | 评估标准                |
| ---------- | ---- | ----------------------- |
| 团队熟悉度 | 30%  | 学习曲线、现有专长      |
| 生态成熟度 | 25%  | 社区活跃、文档质量      |
| 性能指标   | 20%  | Bundle size、运行时性能 |
| 维护成本   | 15%  | 版本稳定性、迁移路径    |
| 扩展性     | 10%  | 插件机制、定制能力      |

## 工作流

### 架构评审清单

- [ ] 需求与约束明确（功能性、非功能性）
- [ ] 备选方案 ≥ 3 个，含"不做"选项
- [ ] 决策矩阵量化评分
- [ ] 风险识别与缓解措施
- [ ] ADR 记录并评审通过
- [ ] 原型验证关键路径

### 输出物

1. **架构文档** - C4 模型（Context、Container、Component、Code）
2. **ADR** - 关键决策记录
3. **接口契约** - TypeScript/Zod/OpenAPI
4. **迁移计划** - 分阶段、可回滚
5. **技术债登记** - 已知妥协、偿还计划

## 质量门禁

- 架构文档在 `.agents/adr/` 版本管理
- 破坏性变更需 ADR + 迁移指南
- 新增依赖需通过选型矩阵评分
